# 관리자 운영 — 지금 할 수 있는 일

올라온 악보를 **고치고·숨기고·되돌리는** 법입니다.
서버에는 관리자 함수가 다 들어갔지만 **화면이 아직 없어서**, 지금은 Supabase 대시보드의
SQL Editor에서 그 함수들을 직접 부릅니다. 웹 관리자 페이지(`admin.html`)가 생기면
4절의 주문이 없어지고 5~9절이 버튼 몇 개로 바뀝니다.

구조와 까닭은 `CLAUDE.md`의 '악보 게시' 절에, 서버는 `server/schema.sql`에 있습니다.

마지막 갱신: 2026-08-21 (관리자 RPC를 들인 날)

---

## 0. 미리 알아 둘 것

- **수정 권한은 브라우저에 있습니다.** 게시할 때 나온 토큰은 올린 사람 컴퓨터에만 있고
  서버에는 해시뿐입니다. 그래서 **남의 악보는 앱에서 못 고칩니다** — 관리자 함수가 지금
  유일한 길입니다.
- **손으로 `update`를 치지 말고 관리자 함수를 부르세요.** 함수는 판을 뜨고 기록을 남기는
  일까지 함께 합니다. 손으로 `update public.scores set doc = …`을 치면 그 둘이 빠지고,
  그러면 되돌릴 근거도 무엇을 왜 고쳤는지도 안 남습니다.
- **`sb_secret_…`(service role) 키는 어떤 파일에도 넣지 마세요.** 그 키는 모든 빗장을
  무시합니다. SQL Editor는 이미 그 권한으로 도니 따로 키를 다룰 일이 없습니다.

## 1. 스키마 적용하기

1. Supabase 대시보드 › **SQL Editor** › New query
2. `server/schema.sql`을 **통째로** 붙여넣고 Run
3. 몇 번을 다시 돌려도 같은 상태가 되게 짜여 있으니, 스키마를 고칠 땐 늘 이 파일을 고쳐
   다시 돌립니다(따로 마이그레이션 파일을 만들지 않습니다).

제대로 들어갔는지:

```sql
select table_name from information_schema.tables
 where table_schema = 'public' order by 1;
-- admins · admin_log · publish_log · score_versions · scores  다섯이 보이면 됩니다
```

이미 올라와 있던 악보들은 마지막 줄의 승계 구문이 v1로 앉힙니다. 확인:

```sql
select count(*) from public.scores;
select count(*) from public.score_versions;   -- 위와 같은 수라야 정상
```

## 2. 관리자 계정 만들기

웹 관리자 페이지를 붙이기 전에는 안 해도 되지만, 먼저 해 두어도 됩니다.

1. 대시보드 › **Authentication › Sign In / Providers › Email**
   → **Allow new users to sign up 끄기**. (아무나 계정을 만들 수 없게)
2. **Authentication › Users › Add user › Create new user**
   → 이메일·비밀번호를 넣고 **Auto Confirm User를 켭니다**(메일 확인 절차를 건너뜁니다).
3. 만들어진 사용자의 **UID**를 복사해 명단에 넣습니다.

```sql
insert into public.admins (uid, name)
values ('여기에-복사한-UID', '한단비내린')
on conflict (uid) do update set name = excluded.name;

select * from public.admins;
```

빗장이 둘인 까닭: 로그인만으로는 관리자가 아니고 **이 명단에 있어야** 관리자입니다.
가입이 어쩌다 열리거나 계정을 하나 더 만들어도 그것만으로는 아무 권한이 없습니다.

## 3. 무엇이 올라와 있나 훑어보기

```sql
select id, ver, title, author, visibility,
       case when hidden_at is null then '' else '내림' end as 상태,
       view_count, created_at::date as 올린날, updated_at::date as 고친날
  from public.scores
 order by created_at desc
 limit 50;
```

특정 지은이만, 또는 제목으로:

```sql
select id, ver, title, author from public.scores
 where title ilike '%영산회상%' or author ilike '%국악원%'
 order by created_at desc;
```

내려간 것만:

```sql
select id, title, author, hidden_at, hidden_reason, hidden_note
  from public.scores where hidden_at is not null order by hidden_at desc;
```

> 국립국악원 OMR 69곡은 지은이가 `국립국악원 (OMR)`입니다. 사람들이 올린 것만 보려면
> `where author <> '국립국악원 (OMR)'`을 붙이세요.

## 4. SQL Editor에서 관리자로 행세하기

3절까지는 표를 그냥 읽는 것이라 아무나 됩니다. **4절부터는 관리자 RPC를 부르는데**,
그 함수들은 `auth.uid()`로 사람을 가립니다. SQL Editor에는 로그인 정보가 없어 그 값이
비어 있으니, 그냥 부르면 이렇게 막힙니다 — 고장이 아니라 정상입니다.

```
ERROR: 관리자만 할 수 있습니다.
```

한 트랜잭션 안에서만 신분을 빌려 씁니다. **아래 5~8절의 모든 SQL은 이 사이에 넣습니다.**

```sql
begin;
select set_config('request.jwt.claims',
                  json_build_object('sub', '여기에-관리자-UID')::text, true);

select public.admin_me();     -- {"uid":"…","name":"한단비내린"} 이 나오면 준비 끝

--  ↓ 여기에 할 일을 적습니다 ↓

commit;     -- 시험이었다면 rollback;
```

`set_config`의 셋째 인자 `true`가 '이 트랜잭션 동안만'이라는 뜻이라 `commit`/`rollback`과
함께 저절로 풀립니다. 웹 관리자 페이지가 생기면 이럴 일이 없습니다 — 진짜 로그인 토큰이
실려 오니까요.

> **왜 손으로 `update`를 치지 않고 RPC를 부르나**
> RPC는 판을 뜨고(`push_version`) 기록을 남기는(`admin_log`) 일까지 함께 합니다.
> 손으로 `update public.scores set doc = …`을 치면 그 둘이 빠지고, 그러면 되돌릴 근거도
> 무엇을 왜 고쳤는지도 남지 않습니다. **급할수록 RPC를 쓰세요.**

## 5. 숨기기 · 다시 열기

**숨김은 `visibility`를 건드리지 않습니다.** `hidden_at`이 따로 있는 까닭이 이것입니다 —
나중에 다시 열면 올린 사람이 골랐던 공개 설정(공개/주소만)이 그대로 돌아옵니다.

### 내리기

```sql
select public.admin_set_hidden(
  'ab12cd34',
  true,
  '저작권 침해 신고에 따른 복제·전송 중단',      -- 공개됩니다
  '신고인 ○○○, 2026-08-21 접수 · 회신 완료'     -- 나만 봅니다
);
```

- 사유는 **필수**입니다(안 적으면 막힙니다). 그 주소를 여는 사람에게
  "게시가 중단된 악보입니다. 사유: …"로 그대로 보이니, 사람이 읽을 말로 적으세요.
- 내린 악보는 모아보기 목록에서도 빠집니다.
- **이미 내려간 것을 다시 내려도 `hidden_at`은 처음 내린 때 그대로입니다.** 그 날짜가
  중단 내역에 적히는 날짜라, 사유를 다듬었다고 중단한 날이 오늘로 바뀌면 안 되니까요.

**저작권 신고로 내렸다면 `notices.html`에 `<tr>` 한 줄을 손으로 더해야 합니다**
(약관 제6조 제4항 — 중단 내역이 게시자 통지를 갈음합니다). 적는 법은 그 파일의
`<tbody>` 주석에 있습니다.

### 다시 열기

```sql
select public.admin_set_hidden('ab12cd34', false);
```

`hidden_note`(내부 메모)는 일부러 남습니다 — 무슨 일이 있었는지의 기록이라 지울 것이 아닙니다.

## 6. 악보 고치기 (문법 교정)

> ⚠️ 약관 제5조에 **교정 조항이 아직 없습니다.** 그 조항을 넣기 전에는, 게시자가
> 요청했거나 명백한 오류를 바로잡는 경우로 좁혀서 쓰세요. 조항 손질은 계획 ⑦번입니다.

### ① 지금 문서를 꺼냅니다

```sql
select jsonb_pretty(public.admin_get_score('ab12cd34') -> 'doc');
```

결과를 통째로 복사해 `고칠악보.jgb.json`으로 저장합니다.

### ② 편집기에서 고칩니다

우물사이를 열고 **파일 ⋯ › 불러오기**로 그 파일을 엽니다.
문법이 틀린 글자에는 선율 에디터에서 **빨간 바탕**이 깔립니다 — 그걸 보고 고칩니다.
다 고쳤으면 **파일 ⋯ › 내보내기**로 다시 `.jgb.json`을 받습니다.

> **[악보 게시]를 누르지 마세요.** 열쇠가 없어 새 게시물이 하나 더 생깁니다.

### ③ 되쓰기 — 한 줄이면 됩니다

`$json$ … $json$`로 감싸면 JSON 안의 따옴표를 신경 쓸 필요가 없습니다.

```sql
select public.admin_save_score(
  'ab12cd34',
  $json$ {여기에 내보낸 JSON 전체} $json$::jsonb,
  '흘림표 토큰 오기 교정 ({흘림} → {흘림표}) · 3각 2정간'
);
-- → {"id":"ab12cd34","ver":4,"changed":true}
```

- **메모는 필수입니다.** 무엇을 왜 고쳤나가 판에 함께 실려야 나중에 게시자도 읽을 수
  있습니다. 빈 메모를 통과시키면 반년 뒤 'v4에서 뭘 고쳤더라'가 됩니다.
- `changed:false`가 나오면 문서가 그대로라는 뜻입니다 — 판도 기록도 안 남습니다.
- 목록에 뜨는 제목, 판, 운영 기록이 **함께** 갱신됩니다.
- **게시자의 수정 열쇠는 그대로 살아 있습니다.** 운영자가 손댔다고 올린 사람이 제 악보를
  못 고치게 되면 그건 교정이 아니라 뺏는 것이라서요.

## 7. 판 보기 · 되돌리기

```sql
select jsonb_pretty(public.admin_versions('ab12cd34'));
--   ver · title · by(user|admin) · editor · note · bytes · created_at
```

특정 판의 내용을 보려면:

```sql
select jsonb_pretty(public.admin_version('ab12cd34', 3) -> 'doc');
```

되돌리기 — **되돌림도 새 판입니다.** 역사를 지우고 과거로 돌아가는 것이 아니라,
과거의 내용을 지금 판으로 다시 채택하는 것입니다. 그래야 언제 누가 되돌렸는지가 남고,
되돌린 것을 다시 되돌릴 수도 있습니다.

```sql
select public.admin_restore('ab12cd34', 3, '교정이 과했다는 게시자 요청');
-- → {"id":"ab12cd34","ver":5,"from_ver":3}
```

판은 최근 20개까지 남고 그보다 오래된 것은 지워집니다. **다만 v1은 안 지워집니다** —
최초 게시본은 게시자의 것이고 신고 처리의 증거이기도 해서입니다.

## 8. 지우기 (마지막 수단)

숨김으로 될 일이면 숨기세요. 지우면 **그 악보의 판까지 함께 사라집니다.**

```sql
select public.admin_delete_score('ab12cd34', '게시자 요청으로 삭제');
```

사유는 필수이고, 지우기 **전에** 제목·지은이·판 수가 운영 기록에 먼저 적힙니다
(지운 뒤에는 꺼낼 수 없으니까요). 그 기록은 악보가 사라져도 남습니다.

## 9. 무슨 일이 있었나 — 운영 기록

```sql
select jsonb_pretty(public.admin_log_list(50, 0));          -- 전체
select jsonb_pretty(public.admin_log_list(50, 0, 'ab12cd34'));  -- 이 악보만
```

`save · hide · unhide · restore · delete` 다섯 가지가 쌓입니다. 문법 검사 결과 적기는
기록하지 않습니다 — 스캔 한 번에 수십 줄이 쌓여 정작 봐야 할 처분 기록이 묻힙니다.

## 10. 잘 되는지 확인하는 SQL

```sql
-- 시험용 악보를 하나 만듭니다. 나오는 id·token 을 아래 <id>·<token> 자리에 넣으세요.
select public.publish_score('{"v":1,"controls":{"title":"시험곡"}}'::jsonb, '시험', 'cc-by');

-- ① 갱신하면 판이 쌓이는가
select public.update_score('<id>', '<token>', '{"v":1,"controls":{"title":"고친 곡"}}'::jsonb);
select ver, title, by_kind, note from public.score_versions
 where score_id = '<id>' order by ver;          -- 두 줄이면 정상

-- ② 같은 문서로 또 갱신하면 판이 안 늘어나는가 (내용이 그대로면 안 올립니다)
select public.update_score('<id>', '<token>', '{"v":1,"controls":{"title":"고친 곡"}}'::jsonb);
select count(*) from public.score_versions where score_id = '<id>';   -- 그대로 2

-- ③ 관리자 RPC가 로그인 없이는 막히는가 (막혀야 정상)
select public.admin_me();      -- ERROR: 관리자만 할 수 있습니다.

-- ④ 신분을 빌리면 되는가 + 내린 악보가 정말 빠지는가
begin;
select set_config('request.jwt.claims',
                  json_build_object('sub','<관리자 UID>')::text, true);
select public.admin_me();
select public.admin_set_hidden('<id>', true, '시험으로 내림');
select public.fetch_score('<id>');   -- '게시가 중단된 악보입니다. 사유: 시험으로 내림'
select public.list_scores();         -- 목록에 없어야 정상
select public.admin_save_score('<id>',
       '{"v":1,"controls":{"title":"교정본"}}'::jsonb, '시험 교정');
select jsonb_pretty(public.admin_versions('<id>'));   -- 판이 셋
select jsonb_pretty(public.admin_log_list(10, 0, '<id>'));  -- hide · save 두 줄
rollback;                            -- 시험이니 통째로 되돌립니다

-- ⑤ 치웁니다 (판도 함께 사라집니다)
select public.delete_score('<id>', '<token>');
select count(*) from public.score_versions where score_id = '<id>';   -- 0
```

브라우저 쪽 빗장도 한 번 확인해 두면 좋습니다 — anon 키로 관리자 RPC를 부르면 막혀야 합니다.

```bash
curl -s "$URL/rest/v1/rpc/admin_list_scores" -X POST \
     -H "apikey: $ANON" -H 'Content-Type: application/json' -d '{}'
# → 권한 없음 (PGRST202 또는 42501)
```

## 11. 아직 못 하는 일 (계획에 있는 것)

| | 무엇 | 되면 달라지는 것 |
|---|---|---|
| ✅② | 관리자 RPC | **끝났습니다.** 판·기록이 저절로 남습니다 |
| ③ | `admin.html` 로그인·목록·숨김 | 4절의 `set_config` 주문이 없어지고, 5절이 버튼 하나로 |
| ④ | 판 보기·되돌리기 화면 | 7절이 목록에서 클릭으로 |
| ⑤ | `index.html#va=<id>` 관리자 열기 | **6절의 ①③이 통째로 없어집니다** — 편집기에서 바로 고치고 [관리자 갱신] |
| ⑥ | `tools/scan-published.mjs` | 문법이 틀린 악보를 **찾아 줍니다**(지금은 눈으로 훑어야 합니다) |
| ⑦ | 약관 교정 조항 | 6절의 경고가 없어집니다 |
